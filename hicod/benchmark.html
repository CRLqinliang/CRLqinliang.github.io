V0.7 / REASONING BENCHMARK

Do concepts improve reasoning?

Hold the robot, scene, candidate solver and call budget fixed; vary the information exposed to the agent. Test whether solution-space concepts improve diagnosis and finite candidate strategy selection.

The available results are a computed finite-action oracle and deterministic smoke tests, not a real LLM comparison. Public designed cases and a shared analytic 3R backend do not establish continuous, dynamic or hardware validity.

01 / CONTROLLED CONDITIONS

Six information profiles, one candidate solver

Every profile receives the same scene and permitted actions. The initial reference-path evaluation counts as one solver call. Each episode allows six solver calls and twelve interaction steps (including submission). Actual geometric probe counts are recorded separately; calls need not have identical costs.

A / BINARY

Binary feedback

Only whether a sampled path was found.

B / LOCAL

Local debugging

Local evidence from one representative attachment and IK branch.

C / RAW

Raw sampled evidence

Paginated states, edges and local validity, without structural summaries.

D / NUMERIC

L4 semantic descriptors

Full HiCoD

Metrics, semantics, evidence drill-down and concept-definition queries.

02 / PUBLIC TASK SUITE

Four finite-action outcome classes

Labels come from enumerating the public action set. The no-witness class means no path was found among the 14 actions, not that the task is infeasible.

22 development and 10 public-test tasks, stratified by strategy category. Both are public, not a secret holdout or an unseen-generalization test.

Public label distribution (avoid before playing)
03 / INTERACTIVE EPISODE

Switch information profiles on the same task

Choose a task and profile, inspect computed feedback, test candidates within budget, and submit a tested action with a witness or explicitly abstain. Reference labels are used for scoring only after submission.

Candidate actions and submission

Actual tool feedback (JSON)

Canonical fields and evidence retain English. Feedback changes with the selected profile.

04 / PIPELINE SMOKE TEST

Scripted sanity checks, not LLM evidence

Run fixed candidate ordering and a hand-written structural-metric rule on all 32 tasks. The policies themselves differ, so results only validate the evaluation/accounting pipeline and do not establish a real model reasoning gain.

Success rate is conditional on tasks with a finite oracle witness. Correct abstention, false abstention, unresolved episodes and diagnosis accuracy are separate.

Full smoke-test record
05 / REAL LLM EXPERIMENT

Run the same model across all six profiles

Use a user-specified chat-completions-compatible endpoint for closed-loop episodes. Record actual token usage, calls, geometric probes and latency; missing token data stays unknown. No real model results have been run yet.
