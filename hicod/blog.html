Why do robot agents need high-level concepts?

From skill libraries to concept libraries: expanding the agent's reasoning space

HiCoD Research NotesNovember 26, 2026Expanded edition · 15 research sectionsResearch perspective · not peer reviewed

The central value of high-level concepts is not teaching a language model more robotics terminology. It is enabling it to reason from the structure of a solution space and decide whether to continue searching, change a manipulation mode, or reformulate the mathematical problem.

01 From failure to problem structure

A motion planner reports that a particular trajectory collides, an inverse-kinematics solver cannot find a configuration, or a joint violates its limit. These are indispensable facts about a candidate. But a robot agent faced with repeated failures must answer a different question: should it continue searching in the same formulation, or change the formulation itself?

HiCoD introduces L4 as the level of sets, relations, distributions and topology over a declared solution family. It sits above individual feasibility checks (L3) and supplies evidence for problem reformulation (L5). This is our working taxonomy, not a standardized hierarchy in robotics.

02 The mathematical object behind a concept

Let x denote the robot, environment, object, task and assumptions; z denotes decision variables such as grasp g, object trajectory τ, base pose b, mode sequence m and joint trajectory q. A formulation M decides which variables are fixed or free and which constraints must hold. The feasible set is relative to M, not a timeless property of the scene.

FM(x) = { z ∈ ZM : CM(x,z) holds }The finite sampled approximation and the continuous feasible set are distinct mathematical objects.

L3 asks whether a specific z belongs to F. L4 asks about a property of F: its projection, connectivity, conditional sections, sensitivity or robustness. L5 changes M. Increasing a search budget leaves the formulation unchanged, while allowing a new manipulation mode or freeing a previously fixed variable changes it. A failed solver can therefore indicate computational insufficiency or a structural restriction, and cannot by itself distinguish the two.

The order of quantifiers matters

For a prescribed object path p(s), let R(s,g,q) mean a valid local realization of grasp g by joint configuration q at stage s. Every stage may admit some grasp without one common grasp spanning all stages. Even a fixed grasp with a valid IK at every stage need not have a continuous joint-space lift.

Local feasibility∀s ∃g,q : R(s,g,q)
Pointwise fixed-attachment feasibility∃g ∀s ∃q : R(s,g,q)
Continuous fixed-attachment realization∃g, continuous q(·) ∀s : R(s,g,q(s))

Implication goes upward; the converse generally fails. The strongest statement still needs all applicable physical and path constraints.

RESEARCH INSIGHT
A useful concept resolves ambiguity in the mathematical question.

High-level language is valuable when it makes different quantifiers, sets and path structures explicit enough to change the next computation.

03 Identical local statistics can demand different decisions

Consider two four-layer sampled graphs. Both have two valid IK slots in each layer, the same endpoint-compatible attachment IDs, eight valid states, and three admitted edges. The only difference is how the edges are arranged. One graph has a complete path; the other does not. Local feasibility counts and even edge counts cannot distinguish them.

Feasible fraction answers a measure question, connectivity a path-existence question, and min-cut a graph-capacity question. They are not interchangeable. A large feasible set can consist of disconnected components; a small one can still contain an excellent route. Similarly, high clearance at most stages cannot compensate for one unavoidable bottleneck. Averages can conceal the exact structure that makes a task difficult.

RESEARCH INSIGHT
A concept earns its place by separating decisions that simpler evidence cannot separate.

Build matched benchmark cases with equal local statistics but different connectivity, or comparable connectivity but different intervention sensitivity. A new concept is justified when existing descriptors cannot discriminate the relevant choices.

04 Choosing what to solve next

A high-level concept is useful when it separates cases that look similar under local feedback but require different interventions. Collision is a symptom; it does not by itself establish whether the best next experiment is a new grasp, a different path, a regrasp, or a new base pose.

These mappings are hypotheses for action selection, not rules that guarantee repair. For example, a small sampled common-grasp set may reflect inadequate sampling. A regrasp should be proposed only when its assumptions and transition conditions can be tested.

05 The task is not its current formulation

A transport task might require moving a rigid object from A to B safely. The implementation may additionally fix the grasp, intermediate path and base pose. Those additional choices are often formulation assumptions rather than task requirements. The agent should identify which assumptions can be changed while retaining the intended outcome.

InterventionWhat changesWhat must remain
More searchBudget, density or initializationSame formulation
ReparameterizeTrajectory basis or variable coordinatesRepresented task semantics
Free variablesInterior path, grasp or base poseHard goal and safety constraints
Add modesSupported regrasp or handoverValid transitions and physical conditions
Diagnostic relaxationCounterfactual removal of a restrictionNo unsafe execution authorization

These changes affect the mathematics differently. Enlarging a decision domain can add witnesses. An equivalent reparameterization can preserve the represented set yet change numerical search. Adding a mode introduces transition relations. Removing a hard constraint for diagnosis changes the counterfactual set and does not change the actual safety requirements.

Counterfactual probes versus failure labels

A collision constraint triggered frequently is not necessarily the unique cause of failure. Test the same domain under a controlled diagnostic removal or permitted parameter change, with matched sampling and solver conditions. If the structural descriptor changes, there is scoped evidence of relevance. Two constraints can interact: removing either alone may have no effect while removing both does. Negative or inconclusive results must remain visible.

Δi = V(FM\i) − V(FM)A controlled contrast in a declared descriptor V; the relaxed model is not authorized for execution.
RESEARCH INSIGHT
Failure attribution is an experiment-design problem.

The agent should ask which test distinguishes inadequate sampling, a narrow transition region and an incompatible formulation, rather than infer a unique cause from a failure label.

06 Formulating optimization problems

Giving an agent access to RRT, MPC, CMA-ES, L-BFGS or a trajectory optimizer does not tell it which variables to expose, which constraints to impose, which objective to optimize, or whether the problem should be decomposed. Those are problem-formulation decisions. High-level concepts can make them better grounded.

Consider a prescribed object path whose payload is clear of obstacles, but whose admissible grasp–IK graph has no start-to-goal path. Optimizing payload clearance alone may miss the restriction. One possible formulation would keep the endpoints and hard physical constraints, expose interior path parameters θ, and penalize a connectivity-related score C(θ).

minθ   Jmotion(θ) + λ C(θ)subject to fixed endpoints and hard physical constraints

A differentiable surrogate may be appropriate for proposing deformations, while a discrete graph or independent physical validator checks the final candidates. A structural score is not a certificate; a non-differentiable or unreliable score may instead call for derivative-free search. The broader idea is that a concept can be both a diagnostic probe and a candidate objective or constraint, depending on its mathematical meaning.

07 From local skills to global feasibility

Even if pick, transfer, handover and place are individually feasible, their feasible input and output states may not match. A grasp that is optimal for picking can destroy all feasible downstream options. This is a limitation of greedy local evaluation, not necessarily a failure of a skill implementation.

Post(Si) ∩ Pre(Si+1) ≠ ∅Necessary boundary compatibility in common coordinates and consistent variable assignments.

Pairwise compatibility is not sufficient for a long chain: the middle skill could accept a state compatible with its predecessor and produce a different compatible output from an unrelated input, without a feasible transition between them. Preserve its input-output relation Tᵢ, not merely the marginal sets. For deterministic transitions, backward continuation sets capture which intermediate states preserve the final goal.

KN = G,   Ki = {x : ∃y ∈ Ki+1, (x,y) ∈ Ti}Backward feasible continuation under a declared deterministic model; robust or stochastic variants require distinct quantifiers.

This connects A04 Skill Compatibility, E02 Cross-Stage Dependency and E06 Future Feasibility Preservation without making them synonyms. They address boundary matching, the impact of a choice on downstream feasible sets, and complete continuation respectively. Such local knowledge can guide a global planner without requiring every individual skill to solve the entire task.

Coupling determines when decomposition is legitimate

Both grasp g and object path τ may have broad feasible projections while most cross-combinations fail. If the joint feasible relation is not the product of its projections, independent searches can produce incompatible choices. Conditioning on a separator s may restore factorization, but only under an explicit scope. Cost coupling must be checked separately from feasibility coupling.

F(g,τ | s) = projgF(·|s) × projτF(·|s)When the equality holds, conditional feasibility factorizes. This is not a claim of statistical independence.
RESEARCH INSIGHT
Skill interfaces should expose future options, not just current success.

A concept may serve as a task-level feasibility interface or separator between solvers, rather than merely a post-failure explanation.

08 Decision-sufficient abstraction

A robot task can generate a very large collection of grasp candidates, IK branches and trajectory samples. Feeding every coordinate, distance and Jacobian to a language model is not necessarily the best way to reason about it. The goal of abstraction is to preserve information that changes decisions, while keeping the original evidence accessible.

We call the target decision-sufficient abstraction: for a specified set of downstream choices, the abstract report should retain enough information to select a good intervention, or indicate that more evidence is necessary. It is task- and decision-dependent, not a claim that one concept can preserve every property of the original space.

This motivates the concept dependency graph: a semantic claim points to the mathematical computation, the finite candidate evidence, and finally the physical checks. Required evidence, optional evidence, specialization and diagnostic association must remain distinct. An association edge is not a causal rule.

09 The agent should choose what to know next

Exhaustively evaluating sixty concepts on every task is not a sensible architecture. Endpoint compatibility may be cheap while multimodal connectivity or robustness evaluation may be expensive. Relevance depends on the current decision and evidence. The agent needs active diagnosis, not a fixed checklist.

Let I denote available information and a an allowed next decision. A query Q returns evidence e. A prospective value-of-information criterion compares optimal expected decision loss before and after observing e, then subtracts the query cost. This is a proposed meta-reasoning formulation, not an implemented estimator in HiCoD.

VOI(Q|I) = mina E[L(a)|I] − Ee|I[mina E[L(a)|I,e]] − C(Q|I)Costs and losses must have compatible units; probabilistic assumptions require explicit modeling.

If a satisfactory reference witness already exists, a costly regrasp query may not improve the decision. If every sampled stage has valid states but there is no fixed-mode route, bridge feasibility may be informative. If no endpoint slot is valid, checking grasp and IK coverage may be preferable. None of these is a universal rule: the potential intervention, its cost and the scope of evidence determine the priority.

Shared evidence changes the economics. One grasp–IK witness pool can support compatibility, sample fractions, reachability and counterfactual comparisons. The marginal cost of a new query depends on what has already been computed. A dependency graph can therefore support computational scheduling and caching, rather than being only an educational visualization.

RESEARCH INSIGHT
Concept selection is itself a decision under limited computation.

A fixed diagnostic pipeline is a useful baseline, but a mature agent should choose, refine or stop queries based on their marginal decision value.

10 Concept contracts and two different graphs

Knowing the word connectivity does not tell a language model whether a particular robot-object-task instance is connected. A concept is a computational instrument, not a glossary entry. It needs a well-defined question, evaluator, result semantics, evidence provenance and uncertainty.

Contract fieldRequired meaning
Domain and assumptionsWhich solution family is analyzed?
Evaluator and representationExact, finite sample, bound or learned surrogate?
Claim and limitationsWhat is established; what remains unknown?
Evidence and dependenciesWhich physical checks support the result?
Resolution and uncertaintyCoverage, model errors and sensitivity
Decision relevanceWhich permitted intervention could be tested?

A sampled witness, an absent sampled witness, an unexecuted query and a proven infeasibility certificate must be distinguishable. A smooth learned connectivity score is a surrogate, not a ground-truth feasibility oracle. Similarly, evidence computed in different coordinate frames or under different task assumptions cannot be composed merely because the names match.

Evidence dependencies are not causal prescriptions

The implemented Concept Graph records required and optional evidence, specialization and diagnostic association. A distinct, proposed intervention graph would connect a structural diagnosis to candidate problem transformations and their applicability tests. The first graph answers how we know; the second asks what we might change. A dependency edge must not be interpreted as a guarantee that its associated intervention succeeds.

Evidence graph (implemented)

IK + collision + path evidence↓Connectivity report↓Scoped conclusion

Intervention graph (proposed)

Observed disconnection↓Test regrasp or deformation↓Verify independently

The graph should support verification, not manufacture certainty.

A grounded agent should be able to report why a query was relevant, what evidence it used, what is unknown and which test could challenge the explanation.

11 A computed manipulation example

The current planar 3R demonstration makes this distinction concrete. In the designed recovery scene, three ideal attachment directions pass both endpoint checks, yet none spans the prescribed sampled path. Allowing an explicitly supported attachment change changes the graph structure rather than merely adding more trials of the same fixed mode.

3Endpoint-compatible modes
0Connected fixed modes
1Minimum graph regrasp count
0/49Successful sampled deformations

Testing 49 midpoint perturbations within a 120 mm budget yielded no fixed-mode sampled path, while a single regrasp at stage 8 produced a graph witness. An agent could use that comparison to prioritize supported regrasp over further searching in this particular deformation family. It cannot conclude that all possible path optimizations fail, that regrasp is globally optimal, or that the real gripper can safely execute the motion.

12 What should transfer across robots and tasks?

The generalization target is not the numeric value of a concept. The shared-grasp set of a planar arm will not numerically transfer to a six-axis industrial robot. What may transfer is the question, the mathematical contract, and the policy for selecting a useful question. New backends must still supply appropriate geometry, kinematics, contact and control evidence.

SettingTransferable querySpecific evidence
Mobile shelf manipulationBase compatibility, cross-stage dependencyBase reachability, shelf and approach geometry
Rigid bimanual carryingCoupling, wrench compatibilityClosed-chain constraints, load sharing
Constrained tool useDirectional margin, bottleneckTool geometry, desired motion and wrench
Object rearrangementBlocking, order, recoverabilityPlacement validity, buffers, interference

A shared concept name may hide different physics. Rigid-transfer connectivity is not the same as contact-mode connectivity in pushing, and a collision-free path does not establish feasible torque or timing. A learned execution policy, geometric solver and structural concept engine should be complementary: none of them alone supplies all the capabilities required for deployment in a new environment.

Abstraction can also hurt: a redundant concept wastes computation, an out-of-scope metric misleads the agent, and a brittle sample statistic can steer search away from an under-sampled viable family. These failure cases should be explicit in the benchmark rather than excluded from demonstration scenes.

13 From skills to concepts

Skill libraries extend what a robot agent can do. Concept libraries extend what it can reason about. Both are needed: the agent needs computationally meaningful descriptions of solution-space structure and executable solvers or skills that can act on them.

CapabilityQuestion
Skill libraryHow can the robot act?
Concept libraryWhat structure does the physical problem have?
Problem formulationWhich mathematical problem should be solved?
Concept discoveryWhat new representation would improve reasoning?

Shared-grasp compatibility, intermediate-pose bridging and grasp–IK trajectory connectivity illustrate how robotics research can become reusable reasoning infrastructure. A concept contribution should include a definition, evaluator, required evidence, interpretation and limitations. An algorithm that happens to use a concept internally is not automatically an agent-facing concept module.

In the long term, a library of composable concepts could help identify gaps in robot reasoning: cases where existing descriptions cannot distinguish useful interventions. Discovering new abstractions to fill those gaps is a different and much harder research problem than selecting a solver. HiCoD is not yet an autonomous roboticist.

14 What would establish the value?

Not every high-level concept is useful, and more abstraction is not always better. If exploring a concept costs more than solving the task directly, or the concept does not change a decision, its operational value can be small. A proposed way to assess this is the expected reduction in downstream decision loss, minus the cost of acquiring and reasoning over the information.

U(c) = E[Lwithout c − Lwith c] − α Cprobe − β CreasonProposed utility model; losses, costs and weights must be defined in compatible units. Not an established HiCoD result.

The existing reasoning benchmark compares six information profiles with the same task and candidate solver: binary outcome, local diagnosis, raw evidence, numerical L4 descriptors, the same numerical descriptors with semantic explanations, and full HiCoD with evidence/definition queries. Numeric versus semantic targets the incremental value of linguistic interpretation; full HiCoD adds further information access, so its result cannot isolate language alone.

A convincing study must include task success, diagnosis accuracy, strategy selection, geometric probes, solver and model calls, tokens, total latency and robustness on held-out tasks. The currently implemented planar examples establish that the evidence pipeline can distinguish several structural cases; they do not establish a general LLM reasoning gain. Broader manipulators, independently verified physical execution and controlled multi-model trials remain necessary.

15 What a convincing experiment must isolate

Showing that a solver benefits from a connectivity score is weaker than showing that an agent uses structural knowledge to improve problem formulation under bounded resources. We must separate gains from additional computation, linguistic interpretation, evidence access and the reasoning policy.

QuestionControlled contrastOutcome
Structural information?Local/raw vs numerical L4, matched total costBetter decisions on matched counterexamples
Language beyond numbers?Identical metrics with vs without explanationsAccuracy and model reasoning cost
Hierarchy?Same initial report; flat vs on-demand evidenceResolution of ambiguous cases
LLM beyond heuristics?Hand-written structural rule vs LLM with identical toolsNovel valid formulations or lower regret
Worth the probe?Direct solver restart vs diagnose-then-solveEnd-to-end success and total cost

A particularly important confound is that a concept evaluator can already solve the same graph search required by the task. In that case an agent may only read out a solution computed by the backend. This can be useful engineering but does not demonstrate a reasoning gain. A strong direct-solver baseline at matched computation is essential. Reserve harder tasks for cases in which a concept informs a different downstream optimization rather than revealing its answer.

The current benchmark tests selection among enumerated interventions. A stronger future benchmark should ask agents to instantiate variable blocks, objective terms, constraint types and allowed mode transitions using a restricted schema, then compile them into a shared solver. Independently defined validators should reject invalid formulations. This would test problem formulation instead of action selection alone.

Measure the quality-cost frontier including unsuccessful probes, preprocessing, model tokens and verification. Use paired tasks, confidence intervals over tasks and seeds, a frozen protocol and a private holdout. Include cases where direct planning is cheap and concepts should not help. If the agent cannot outperform a cheap structural heuristic at matched cost, that is a meaningful negative result.

RESEARCH INSIGHT
The decisive test is better decisions, not knowledge of names.

A falsifiable research program should reveal which abstractions, task families and budgets do not justify the added reasoning layer.

From expanding the robot's action space to expanding the agent's reasoning space.

This is the research direction behind HiCoD. Debugging is the initial application; grounded problem formulation is the larger goal.
