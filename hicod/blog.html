Why do robot agents need high-level concepts?

From skill libraries to concept libraries: expanding the agent's reasoning space

HiCoD Research NotesNovember 26, 2026Research perspective · not peer reviewed

The central value of high-level concepts is not teaching a language model more robotics terminology. It is enabling it to reason from the structure of a solution space and decide whether to continue searching, change a manipulation mode, or reformulate the mathematical problem.

01 From failure to problem structure

A motion planner reports that a particular trajectory collides, an inverse-kinematics solver cannot find a configuration, or a joint violates its limit. These are indispensable facts about a candidate. But a robot agent faced with repeated failures must answer a different question: should it continue searching in the same formulation, or change the formulation itself?

HiCoD introduces L4 as the level of sets, relations, distributions and topology over a declared solution family. It sits above individual feasibility checks (L3) and supplies evidence for problem reformulation (L5). This is our working taxonomy, not a standardized hierarchy in robotics.

02 Choosing what to solve next

A high-level concept is useful when it separates cases that look similar under local feedback but require different interventions. Collision is a symptom; it does not by itself establish whether the best next experiment is a new grasp, a different path, a regrasp, or a new base pose.

These mappings are hypotheses for action selection, not rules that guarantee repair. For example, a small sampled common-grasp set may reflect inadequate sampling. A regrasp should be proposed only when its assumptions and transition conditions can be tested.

03 Formulating optimization problems

Giving an agent access to RRT, MPC, CMA-ES, L-BFGS or a trajectory optimizer does not tell it which variables to expose, which constraints to impose, which objective to optimize, or whether the problem should be decomposed. Those are problem-formulation decisions. High-level concepts can make them better grounded.

Consider a prescribed object path whose payload is clear of obstacles, but whose admissible grasp–IK graph has no start-to-goal path. Optimizing payload clearance alone may miss the restriction. One possible formulation would keep the endpoints and hard physical constraints, expose interior path parameters θ, and penalize a connectivity-related score C(θ).

minθ   Jmotion(θ) + λ C(θ)subject to fixed endpoints and hard physical constraints

A differentiable surrogate may be appropriate for proposing deformations, while a discrete graph or independent physical validator checks the final candidates. A structural score is not a certificate; a non-differentiable or unreliable score may instead call for derivative-free search. The broader idea is that a concept can be both a diagnostic probe and a candidate objective or constraint, depending on its mathematical meaning.

04 Decision-sufficient abstraction

A robot task can generate a very large collection of grasp candidates, IK branches and trajectory samples. Feeding every coordinate, distance and Jacobian to a language model is not necessarily the best way to reason about it. The goal of abstraction is to preserve information that changes decisions, while keeping the original evidence accessible.

We call the target decision-sufficient abstraction: for a specified set of downstream choices, the abstract report should retain enough information to select a good intervention, or indicate that more evidence is necessary. It is task- and decision-dependent, not a claim that one concept can preserve every property of the original space.

This motivates the concept dependency graph: a semantic claim points to the mathematical computation, the finite candidate evidence, and finally the physical checks. Required evidence, optional evidence, specialization and diagnostic association must remain distinct. An association edge is not a causal rule.

05 A computed manipulation example

The current planar 3R demonstration makes this distinction concrete. In the designed recovery scene, three ideal attachment directions pass both endpoint checks, yet none spans the prescribed sampled path. Allowing an explicitly supported attachment change changes the graph structure rather than merely adding more trials of the same fixed mode.

3Endpoint-compatible modes
0Connected fixed modes
1Minimum graph regrasp count
0/49Successful sampled deformations

Testing 49 midpoint perturbations within a 120 mm budget yielded no fixed-mode sampled path, while a single regrasp at stage 8 produced a graph witness. An agent could use that comparison to prioritize supported regrasp over further searching in this particular deformation family. It cannot conclude that all possible path optimizations fail, that regrasp is globally optimal, or that the real gripper can safely execute the motion.

06 From skills to concepts

Skill libraries extend what a robot agent can do. Concept libraries extend what it can reason about. Both are needed: the agent needs computationally meaningful descriptions of solution-space structure and executable solvers or skills that can act on them.

CapabilityQuestion
Skill libraryHow can the robot act?
Concept libraryWhat structure does the physical problem have?
Problem formulationWhich mathematical problem should be solved?
Concept discoveryWhat new representation would improve reasoning?

Shared-grasp compatibility, intermediate-pose bridging and grasp–IK trajectory connectivity illustrate how robotics research can become reusable reasoning infrastructure. A concept contribution should include a definition, evaluator, required evidence, interpretation and limitations. An algorithm that happens to use a concept internally is not automatically an agent-facing concept module.

In the long term, a library of composable concepts could help identify gaps in robot reasoning: cases where existing descriptions cannot distinguish useful interventions. Discovering new abstractions to fill those gaps is a different and much harder research problem than selecting a solver. HiCoD is not yet an autonomous roboticist.

07 What would establish the value?

Not every high-level concept is useful, and more abstraction is not always better. If exploring a concept costs more than solving the task directly, or the concept does not change a decision, its operational value can be small. A proposed way to assess this is the expected reduction in downstream decision loss, minus the cost of acquiring and reasoning over the information.

U(c) = E[Lwithout c − Lwith c] − α Cprobe − β CreasonProposed utility model; losses, costs and weights must be defined in compatible units. Not an established HiCoD result.

The existing reasoning benchmark compares six information profiles with the same task and candidate solver: binary outcome, local diagnosis, raw evidence, numerical L4 descriptors, the same numerical descriptors with semantic explanations, and full HiCoD with evidence/definition queries. Numeric versus semantic targets the incremental value of linguistic interpretation; full HiCoD adds further information access, so its result cannot isolate language alone.

A convincing study must include task success, diagnosis accuracy, strategy selection, geometric probes, solver and model calls, tokens, total latency and robustness on held-out tasks. The currently implemented planar examples establish that the evidence pipeline can distinguish several structural cases; they do not establish a general LLM reasoning gain. Broader manipulators, independently verified physical execution and controlled multi-model trials remain necessary.
